## 1. 防抖（Debounce）

### 1.1 原理

**防抖**的含义：在事件被连续触发时，只在该事件**停止触发一段时间后**才执行一次处理函数。

- 每次新事件到来时，会**取消**上一次尚未执行的定时器，并重新设定一个延迟定时器。
- 若在延迟时间内再次触发，则再次取消并重设，直到“最后一次触发”后的延迟时间结束，才真正执行一次。

数学上可以理解为：  
**执行时机 = 最后一次事件发生时间 + 延迟时间 delay**。

### 1.2 适用场景

- **搜索输入框**：用户每敲一个字就发请求会造成请求过多、卡顿；用防抖后仅在“停止输入约 300ms”后发一次请求或更新联想列表。
- 窗口 resize、表单校验等“连续触发、只需在停顿时反应一次”的场景。

### 1.3 本项目中实现位置

- **实现**：`js/utils.js` 中的 `debounce(fn, delay)`。
- **使用**：`js/search.js` 中搜索输入框的 `input` 事件，使用 `Utils.debounce(doFilterUpdate, 300)`，即 300ms 防抖。

### 1.4 代码要点

```javascript
// utils.js 核心逻辑
function debounce(fn, delay) {
  var timer = null;
  return function () {
    var args = arguments, ctx = this;
    if (timer) clearTimeout(timer);   // 取消上一次
    timer = setTimeout(function () {
      fn.apply(ctx, args);            // 延迟后执行
      timer = null;
    }, delay);
  };
}
```

- 使用 `clearTimeout` 取消前一次定时器，保证“只认最后一次”。
- 使用 `apply(ctx, args)` 保持调用时的 `this` 和参数，便于在搜索回调里正确访问 `input` 等 DOM。

## 2. 节流（Throttle）

### 2.1 原理

**节流**的含义：在事件持续触发时，**按固定时间间隔**最多执行一次处理函数。

- 记录上次执行时间 `last`，每次事件触发时若 `now - last >= delay` 才执行并更新 `last`。
- 这样在连续滚动、resize 等场景下，不会每帧都执行，从而降低 CPU 占用、避免卡顿。

### 2.2 适用场景

- **滚动事件**：导航栏“滚动后由透明变实色”、回到顶部按钮显示/隐藏，不需要每毫秒都算，约 100ms 执行一次即可。
- 拖拽、窗口 resize 等“高频率触发、只需按间隔响应”的场景。

### 2.3 本项目中实现位置

- **实现**：`js/utils.js` 中的 `throttle(fn, delay)`。
- **使用**：
  - `js/nav.js`：`Utils.throttle(onScroll, 100)`，滚动时更新导航栏样式。
  - `js/back-to-top.js`：滚动时控制“回到顶部”按钮显示，同样使用节流。

### 2.4 代码要点

```javascript
// utils.js 核心逻辑
function throttle(fn, delay) {
  var last = 0;
  return function () {
    var now = Date.now();
    if (now - last >= delay) {
      last = now;
      fn.apply(this, arguments);
    }
  };
}
```

- 时间戳方式实现，保证在 delay 内最多执行一次，且首次触发会立即执行（若 last 为 0）。

## 3. 3D 变换与相册

攻略页的“3D 相册”包含两部分：**整体拖动旋转**（rotateX/rotateY）和**单卡翻页**（rotateY 180°）。

### 3.1 CSS 3D 基础概念

- **perspective（透视）**  
  在父容器上设置 `perspective: 1000px`，表示“观察者距离变换平面 1000px”。数值越小，透视越强、立体感越明显；越大则越接近正交投影。

- **transform-style: preserve-3d**  
  使子元素在 3D 空间中参与变换，而不是被压平到 2D 平面。相册容器和卡片内层都使用了该属性。

- **rotateX / rotateY**  
  - `rotateX(θ)`：绕水平轴（X 轴）旋转，对应“上下拖动”的视觉效果。
  - `rotateY(θ)`：绕垂直轴（Y 轴）旋转，对应“左右拖动”的视觉效果。  
  角度单位为 deg，正方向遵循右手系。

- **backface-visibility: hidden**  
  卡片正面和背面分别用 `.gallery-3d-front` 和 `.gallery-3d-back`，背面设置 `rotateY(180deg)` 并配合 `backface-visibility: hidden`，这样翻到背面时正面不可见，避免“透过去”的穿帮。

### 3.2 鼠标位移与旋转角度的换算

整体旋转由 `guide.html` 内联脚本实现：

- 记录 `mousedown` 时的 `(downX, downY)` 和当前用于积分的 `(startX, startY)`。
- 在 `mousemove` 中计算本帧位移：
  - `dx = e.clientX - startX`
  - `dy = e.clientY - startY`
- 累加到全局角度：
  - `baseRotateY += dx * 0.4`（水平位移 → 绕 Y 轴）
  - `baseRotateX -= dy * 0.4`（垂直位移 → 绕 X 轴，取反是为了符合“向上拖即相册向上转”的直觉）
- `baseRotateX` 用 `Math.max(-30, Math.min(30, baseRotateX))` 限制在 ±30°，避免上下翻转过度。

系数 `0.4` 是“像素→角度”的灵敏度，可根据体验调整；答辩时可说明：**鼠标移动的像素与旋转角度成线性关系，通过系数控制手感**。

### 3.3 requestAnimationFrame 限频

在 `mousemove` 中不直接写 `applyTransform()`，而是：

```javascript
if (!rafId) {
  rafId = requestAnimationFrame(applyTransform);
}
```

这样在同一帧内多次 `mousemove` 只触发一次 DOM 更新（一次 `applyTransform`），既保证流畅又避免重复计算和重排，是常见的“节流式”用法。

### 3.4 翻页（点击翻转）

- 卡片内层 `.gallery-3d-card-inner` 默认 `rotateY(0deg)`，背面已预先 `rotateY(180deg)` 且 `backface-visibility: hidden`。
- 点击时给卡片加上 `.flipped`，内层变为 `transform: rotateY(180deg)`，通过 CSS transition 做 0.6s 的平滑翻转。
- 通过 `mouseup` 时判断“移动距离是否小于 8px”区分“点击”与“拖动”，只有点击才 `toggle('flipped')`。

### 3.5 本项目中文件位置

- **HTML/逻辑**：`guide.html` 中 3D 相册的脚本（约 192–251 行）。
- **样式**：`css/components.css` 中 `.gallery-3d-*` 相关（约 1291–1366 行）。

## 4. 打字机效果（Typewriter）

### 4.1 原理

在目的地搜索联想中，每条结果的“名称”和“城市”不是一次性 `textContent = "xxx"`，而是**按字符逐个追加**，并配合约 30ms 的间隔，形成“打字机”效果。

### 4.2 实现位置与流程

- **实现**：`js/search.js` 中的 `typewriter(el, text, cb)`。
- **流程**：
  1. 清空 `el.textContent`，从索引 0 开始。
  2. 每 30ms 向 `el` 追加一个字符 `text[i]`，`i++`。
  3. 当 `i >= text.length` 时结束，并调用回调 `cb`。
- 联想列表渲染时，先对“名称”做一次 typewriter，完成后再对“城市”做 typewriter，再继续下一条（`appendNext`），形成逐条、逐字段的打字效果。

### 4.3 与防抖的关系

- 输入框使用**防抖**减少输入过程中的频繁筛选和渲染。
- 防抖触发后才会更新联想列表并执行**打字机**展示；二者配合既控制性能，又保留展示上的动效。
